[fence-movement-unknown]
A fence contribution arrived naming a data movement this build does not
implement.  Every daemon in a DVM is built from the same source, so this
is a defect rather than a version difference.

  Node:     %s
  Movement: %lu

The fence has been ended with an error rather than guessed at.  Please
report this, including the output of "prte_info --all".
#
[fence-movement-mismatch]
Two daemons disagreed about how a fence's contributions were being
gathered.  Each participant in a fence chooses this independently, and
they must all reach the same answer; when they do not, the collective
can never converge, because some daemons would wait for a result that
the others are not going to send.

  Node:            %s
  We chose:        %s
  Reported by:     %s
  Which chose:     %s

The fence has been ended with an error rather than left to hang.  The
usual cause is daemons running with different values of the
"grpcomm_fence_movement" MCA parameter - it must be the same everywhere,
so set it on the DVM rather than on an individual job.  If it is already
uniform, please report this, including the output of "prte_info --all".
